Problem: Two generation entry points (AIService.generateNovel vs NovelService.generateFull). Layer generators bypass AIService, so API keys, quotas and custom base URLs don't apply. Two services hardcode 'deepseek'. LLMFactory is a static registry — prevents test isolation.

Solution: Make AIService the single provider creation seam. Inject it into Layer generators. Remove LLMFactory static registry; replace with instance-based pool managed by AIService. Delete AIService.generateNovel(); route all generation through NovelService.

  • Wins: Locality — provider config lives in one module
  • Wins: Leverage — quota enforcement reaches all generation paths
  • Wins: Testability — inject mock provider instead of touching global registry
  • Wins: Delete 2 hardcoded provider strings
  • ADR: ADR-0001 (Flutter stack) unaffected; ADR-0002 (World as core) neutral

Problem: Interface of each repository is nearly as wide as its implementation — getX(), createX(), updateX(), deleteX() — no encapsulation, transactions, caching or domain logic. WorldService and CanonService bypass them for half their writes. Copy-paste bug in WorkRepository.deleteVolume().

Solution: Option A (recommended): remove the repository layer. Let services call Drift directly through DatabaseManager with a shared query helper. ~800 lines of boilerplate to delete. Option B: deepen repositories by moving transaction control, caching, and event emission behind them — but this adds complexity and every existing bypass would need rewiring.

  • Wins: Interface shrinks — one DatabaseManager instead of 8 repo interfaces
  • Wins: Locality — data access logic concentrates, not scatters
  • Wins: Delete 1 copy-paste bug
  • Wins: Eliminate 8× repeated _db() boilerplate

Problem: Four pages account for ~3,900 lines — nearly half the lib/ codebase. Business logic (stats computation, Drift queries, LLM calls) interleaved with widget construction. Zero widget tests. Every page accesses ServiceLocator.instance directly, making substitution impossible. State is ad-hoc setState everywhere.

Solution: Extract a ViewModel per page — DashboardViewModel, EditorViewModel, WorkspaceViewModel — receiving services as constructor parameters. Pages become thin wrappers that receive a ViewModel and render its state. Use ValueNotifier or a lightweight state holder to replace setState.

  • Wins: Testability — DashboardViewModel unit-testable without rendering a widget
  • Wins: Locality — stats logic lives in one place, not inline in build()
  • Wins: Interface shrinks — pages accept one ViewModel param instead of pulling global state
  • Wins: ~3,000 lines of widget tree become ~600 lines of ViewModel + ~600 lines of widget

Top recommendation: Candidate 1 — AI generation pipeline

This is the core product feature with the widest blast radius. Every AI-powered feature in the app (generation, analysis, detection) bypasses AIService's configuration. Fixing this seam unlocks testability for the LLM layer, makes quota enforcement universal, and removes two hardcoded provider strings. The other candidates are real but less customer-facing — Candidate 2 (repositories) is mostly an internal hygiene issue, and Candidate 3 (ViewModel extraction) is important for test coverage but doesn't block correctness.
