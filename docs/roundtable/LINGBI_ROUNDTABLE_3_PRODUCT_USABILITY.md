# 灵笔第三次圆桌会议：产品可用性审计与商业化门槛

> 会议时间：2026-07-24（第三次）
> 触发原因：用户首次真实使用灵笔写作后发现四个阻断性体验问题
> 核心判断：**有完整生产性的可能，但没有商业化的条件**

## 与会角色

| 角色 | 视角 |
|------|------|
| **产品总监 (PD)** | 用户体验、商业化门槛、竞品对标 |
| **AI 架构师 (AI)** | 模型路由、Prompt 工程、思考链处理 |
| **前端主管 (FE)** | Flutter UI 交互、信息密度、可发现性 |
| **技能系统设计师 (SK)** | 技能可发现性、触发机制、与对话的融合 |

## 一、用户原话与问题定义

> "我明明就只填了一个供应商，这供应商里面还有很多个模型，结果你都没有让我来控制，我都不知道我使用的是供应商里面哪个模型。"

**问题 1：模型选择不透明**

> "AI 并没有那些模板和 skill，我也不知道怎么动用这些 skill，相当于很多功能有了，但并没有怎么让人使用。"

**问题 2：技能系统不可见、不可触达**

> "AI 输出的思考应该像可以折叠的那一种，输出完之后就折叠回来，给出思考的结果。不然上下文太长了。"

**问题 3：思考链/推理过程未折叠，信息过载**

> "我跟这个 AI 对话的时候，他都没有提问我什么，就直接自己开写了。这样既会浪费我的 token，也会导致项目要重新修改很多次。"

**问题 4：AI 不提问就开写，浪费 token 且结果不可控**

## 二、竞品对标分析

### OpenWrite App v1.2.6 的做法

| 问题 | OpenWrite 方案 |
|------|---------------|
| 模型选择 | 设置页明确显示当前模型 ID；自定义端点配置时 modelId 为必填字段；写作前状态栏显示 `model: xxx` |
| 技能触达 | 编辑器工具栏有 `/command` 斜杠菜单；右键菜单集成技能；AI 面板有技能快捷入口 |
| 思考折叠 | 使用 `<details>` 式折叠块；流式输出时展开，完成后自动折叠为摘要行 |
| 提问机制 | 首次写作前 AI 主动提问（目标字数、情绪走向、关键事件）；用户可跳过但默认提问 |

### OpenWrite CLI v5.8.0 的做法

| 问题 | OpenWrite CLI 方案 |
|------|-------------------|
| 模型选择 | `--model` 参数显式指定；配置文件 `[provider]` 段有 `model = "xxx"` |
| 技能触达 | `/skill list` 列出所有技能；`/skill run <name>` 执行；写作 prompt 自动注入相关技能 |
| 思考折叠 | `--verbose` 控制是否显示推理；默认只显示最终输出 |
| 提问机制 | `--interactive` 模式下先问 3-5 个问题再动笔；`--yes` 跳过提问 |

### 成熟 AI 写作产品通用模式

- **NovelAI**：模型选择下拉框在生成按钮旁边，一目了然
- **Sudowrite**：写作前弹出 "Story Engine" 面板，先确认方向再生成
- **ChatGPT Canvas**：思考过程用灰色折叠块，点击展开

## 三、逐项裁决

### 裁决 1：模型选择透明化

**现状问题**：
- `CustomEndpointConfig` 有 `modelId` 字段，但 UI 上用户看不到当前使用的是哪个模型
- `OpenAIProvider._modelId` 默认 `gpt-4o-mini`，用户完全不知道
- 设置页只有"供应商"选择，没有"模型"选择

**裁决**：

1. **AI 面板顶部显示当前模型标识**
   - 格式：`[供应商名] / [模型ID]`
   - 点击可切换模型

2. **设置页自定义端点增加模型下拉**
   - 调用 `/v1/models` 接口获取可用模型列表
   - 用户选择后保存到 `CustomEndpointConfig.modelId`

3. **写作面板生成前显示模型**
   - 在"AI 写作"按钮下方显示 `将使用: deepseek-chat`
   - 允许临时切换

4. **AIService 暴露 `currentModelId` 属性**
   - 所有 Provider 实现 `String get modelId`
   - UI 层读取并显示

**优先级**：P0（阻断性——用户不知道自己在用什么）

---

### 裁决 2：技能系统可发现、可触达

**现状问题**：
- 17 个技能存在于 `community/skills/` 目录
- 技能市场页面可以安装/卸载
- 但 AI 对话完全不知道这些技能的存在
- 用户无法在写作时触发技能
- 技能只是 Markdown 文档，没有程序化触发路径

**裁决**：

1. **AI 对话框支持 `/技能名` 斜杠命令**
   - 输入 `/` 弹出已安装技能列表
   - 选择后自动构建对应 prompt 模板
   - 示例：`/续写` → 自动取当前编辑器选中文本 + 续写 prompt

2. **编辑器右键菜单集成技能**
   - 选中文本 → 右键 → "AI 技能" 子菜单
   - 列出适用于选中文本的技能（续写、润色、风格分析等）

3. **AI 面板快捷操作扩展**
   - 现有 `_showQuickActions()` 只有 3 个硬编码项
   - 改为从已安装技能动态生成
   - 每个技能有 `trigger`（触发词）和 `prompt_template`

4. **技能注册表程序化**
   - `community/skill-registry.json` 增加 `trigger`、`category`、`input_type` 字段
   - `SkillService` 加载已安装技能，提供 `List<SkillCommand>` 给 UI

5. **AI 系统 prompt 注入技能感知**
   - 告诉 AI："用户已安装以下技能：续写、润色、风格蒸馏…如果用户的请求匹配某个技能，主动建议使用。"

**优先级**：P0（功能存在但不可用 = 不存在）

---

### 裁决 3：思考链折叠

**现状问题**：
- `ChatWidget` 直接渲染全部文本，无结构化处理
- 如果模型返回 `<think>...</think>` 或 `让我思考一下...` 等推理内容，全部平铺显示
- 上下文迅速膨胀，用户找不到最终结果

**裁决**：

1. **ChatEntry 增加结构化字段**
   ```dart
   class ChatEntry {
     final String role;
     final String content;        // 最终输出
     final String? thinking;      // 思考/推理过程
     final bool isStreaming;
     final bool isThinkingCollapsed; // 思考是否折叠
   }
   ```

2. **流式输出时实时分离思考与正文**
   - 检测 `<think>` / `</think>` 标签
   - 检测 `---` 分隔符前的推理段落
   - 思考部分用灰色斜体 + 折叠容器显示
   - 正文部分正常显示

3. **完成后自动折叠思考**
   - 流式结束 → `isThinkingCollapsed = true`
   - 显示为一行摘要：`💭 思考过程 (点击展开)`
   - 点击展开查看完整推理

4. **设置项控制**
   - "显示 AI 思考过程"：开/关/仅摘要
   - 默认：仅摘要（折叠）

**优先级**：P1（体验问题，不阻断功能但严重影响可用性）

---

### 裁决 4：AI 先提问再动笔

**现状问题**：
- `_sendMessage()` 直接把用户消息发给 AI，无任何引导
- AI 写作面板的 `userInstruction` 是可选的，用户可以什么都不填就点生成
- 没有"确认方向"环节
- 结果：AI 自行脑补方向 → 浪费 token → 用户不满意 → 重新生成 → 循环

**裁决**：

1. **写作前引导提问（Writing Preflight Interview）**
   - 用户点击"AI 写作"后，如果未填写写作要求：
     - AI 先提问 2-3 个问题：
       - "这一章的核心事件是什么？"
       - "情绪走向？（紧张/舒缓/高潮/过渡）"
       - "有没有必须出现/不能出现的内容？"
     - 用户回答后再生成
   - 如果用户已填写详细要求（>50字），跳过提问直接生成

2. **对话模式增加"澄清"能力**
   - 系统 prompt 增加指令：
     > "如果用户的请求模糊（少于20字且无具体方向），先提出1-2个澄清问题，确认方向后再输出。不要直接开写。"
   - 用户可以用 `/直接写` 跳过提问

3. **写作面板增加"快速方向"选择器**
   - 在写作要求输入框上方增加快捷标签：
     - 情绪：`紧张` `舒缓` `悲伤` `热血` `日常`
     - 节奏：`快节奏` `慢节奏` `过渡`
     - 目标：`推进主线` `角色发展` `世界观展开` `伏笔`
   - 点击标签自动填入写作要求

4. **Token 预估显示**
   - 生成前显示预估消耗：`预计消耗 ~2000 token`
   - 让用户有成本意识

**优先级**：P0（直接浪费用户金钱）

## 四、实施优先级排序

| 优先级 | 项目 | 工作量 | 理由 |
|--------|------|--------|------|
| **P0-1** | 模型选择透明化 | 2h | 用户不知道在用什么 = 不信任 |
| **P0-2** | AI 先提问再动笔 | 3h | 直接浪费金钱 |
| **P0-3** | 技能斜杠命令 | 4h | 功能不可用 = 不存在 |
| **P1-1** | 思考链折叠 | 3h | 信息过载影响体验 |
| **P1-2** | 编辑器右键技能菜单 | 3h | 提升可发现性 |
| **P1-3** | 快速方向选择器 | 2h | 降低使用门槛 |
| **P2-1** | `/v1/models` 模型列表拉取 | 2h | 锦上添花 |
| **P2-2** | Token 预估显示 | 1h | 成本透明 |

## 五、商业化门槛清单

用户判断"有生产性可能，没有商业化条件"。以下是达到商业化最低门槛的差距：

| 维度 | 当前状态 | 商业化最低要求 |
|------|----------|----------------|
| 模型控制 | 用户不知道用什么模型 | 明确显示+可切换 |
| 功能可发现性 | 17个技能藏在目录里 | 对话中可触达 |
| 信息架构 | 思考+正文混排 | 分层折叠 |
| 交互引导 | AI 不提问就开写 | 先确认方向再动笔 |
| 成本透明 | 无 token 计量显示 | 预估+实际消耗 |
| 错误恢复 | 有但用户不知道 | 明确状态+引导 |
| 首次体验 | 打开后不知道干什么 | 引导流程 |

---

## 六、本轮不做的事

- 不重构 AI Provider 架构
- 不增加新的 AI 供应商
- 不做 RAG / 向量召回
- 不做世界线 / 承诺台账
- 不做多 Agent 协作
- 不改动写作流水线核心逻辑（已验证）

---

## 七、验收标准

本轮完成后，用户应能：

1. ✅ 在 AI 面板看到当前使用的模型名称
2. ✅ 在对话框输入 `/` 看到已安装技能列表并触发
3. ✅ AI 思考过程默认折叠，点击可展开
4. ✅ 模糊请求时 AI 先提问确认方向
5. ✅ 写作面板有快速方向标签
6. ✅ 生成前显示将使用的模型
