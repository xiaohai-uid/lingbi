# ADR-0001: 引导式 AI 采用三层混合架构

## 状态

已接受 (2026-07-25)

## 背景

灵笔需要从"被动应答"转向"AI 主动引导"的创作范式。实现引导式 AI 有三种纯方案：

- **纯状态机**：新建 GuidedFlowEngine 完全控制对话，AI 只是模板填充器
- **纯对话编排**：保持 chat() 不变，靠 system prompt 注入让 AI "自己决定"引导步骤
- **纯 Skill**：每个引导流程是一个 Skill，复用 Skill Runtime

纯方案各有致命缺陷：状态机太僵硬（用户无法自由发挥）；纯对话不可控（AI 可能跑偏）；纯 Skill 缺乏跨步骤状态追踪。

## 决策

采用三层混合架构：

1. **编排层 (GuidedFlowEngine)**：数据驱动的轻量状态机，负责步骤推进、完成判定、分支处理。步骤定义在 YAML/JSON 中，不硬编码。
2. **内容层 (题材 Skill)**：提供领域知识、system prompt 模板、结构化约束。社区可替换/扩展。
3. **执行层 (AIService.chat())**：现有 LLM 调用能力不变，只接收编排层注入的 prompt。

关键约束：
- 用户随时可跳出引导进入自由对话，引导状态暂停但不丢失
- 每步产出自动写入 Canon/项目文件（AI 直接读写）
- Skill Runtime 需新增"多轮有状态对话"能力

## 后果

- 正面：题材引导可由社区贡献，核心引擎保持稳定；用户既有引导又有自由度
- 负面：三层之间的接口契约需要严格定义；Skill Runtime 需要扩展状态管理能力
- 风险：如果编排层的"完成判定"过于机械（关键词匹配），体验会退化为填表；需要 AI 辅助判定
