# 向导两屏交互模型与第一章生成旅程

v1.2 向导存在两个结构性问题：所有 5 步均为自由文本输入，但题材/字数/平台/创意方向应为选择题（用户明确投诉：「有一些选项明明是B选项，你为什么还是给我整成选填啊？」）；向导完成后跳转空编辑器，第一章候选正文不可见（核心价值链断裂，Bug A）。决定重做为两屏结构（快速选择屏 + 深度填写屏），完成后自动导航到编辑器流式展示第一章。

## Considered Options

- **A. 保持 5 步单步卡片，仅更换输入控件**：改动最小，但步骤膨胀到 8-9 步，流程更长，"快速建书"价值主张不成立。
- **B. 两屏分组（选定）**：第一屏集中 3 个选择型维度（题材 + 字数 + 平台），10 秒完成骨架；第二屏混合自由文本 + 选择型，深化创作上下文。屏数少、每屏聚焦。
- **C. 单屏表单**：所有维度平铺一页。信息密度过高，吓退写作新手，且无法制造"填完即生成"的即时满足感。

## Decisions

### 屏结构

| 屏 | 维度 | 交互型 | 必选性 |
|----|------|--------|--------|
| 第一屏：快速选择 | 题材 | B 型（多选 ≤3） | 必选 |
| | 字数目标 | B 型（单选） | 必选 |
| | 发布平台 | B 型（单选） | 必选 |
| 第二屏：深度填写 | 书名 | A 型（自由文本） | 可跳过，默认"未命名作品" |
| | 主角描述 | A 型（自由文本，不限字数） | 必填，不可跳过 |
| | 世界观 | A 型（自由文本，不限字数） | 可跳过，默认空（跳过时不注入正典） |
| | 创意方向 | B 型（多选 ≤3，4-5 张全展示） | 可跳过，默认"通用" |
| | 第一章目标 | A 型（自由文本，不限字数） | 必填，不可跳过 |

### 卡片选择器语义

- **题材选项源**：起点中文网 14 个一级分类（玄幻、奇幻、武侠、仙侠、都市、现实、军事、历史、游戏、体育、科幻、诸天无限、悬疑灵异、轻小说）
- **题材展示**：默认 6 张热门卡片（玄幻、都市、仙侠、悬疑灵异、科幻、奇幻）+ "更多"按钮展开全部 14 个的完整网格（展开后为搜索结果视图，覆盖原卡片区域）
- **多选上限**：题材和创意方向均为 3
- **字数目标选项**（单选，全展示）：短篇(3-5万)、中篇(10-20万)、长篇(50万+)、连载(100万+)
- **发布平台选项**（单选，全展示）：起点、番茄、晋江、七猫、自由发布
- **创意方向选项**（多选 ≤3，全展示）：爽文升级、悬疑反转、虐恋情深、日常温馨、热血争霸
- **自定义入口**：每个卡片组底部"+ 自定义"，展开 TextField；与卡片选择**共存**（非互斥）；有格式校验（非空）
- **权重语义**：UI 层不区分主题材/副题材；权重由用户在第二屏自由文本中描述，ContextCompiler 将多选结果 + 描述文本一并传入 AI

### 导航与校验

- 第一屏"下一步"按钮：三个维度全有值才可点击；未满足时点击 → Toast「请至少选择一个题材」
- 第二屏"返回上一屏"→ 二次确认弹窗（「确定要返回吗？当前填写内容将清空」）→ 确认后**两屏全部数据清空**，回到第一屏初始状态
- 向导完成后**不可重新走向导**；正典面板仍可正常编辑角色/设定（那是正典域的事）

### 第一章生成旅程（Bug A 修复）

```
第二屏点击"完成"
  → 立即导航到编辑器（先跳转，不在向导页等待）
  → 编辑器内显示 loading（进度条 + "AI 正在创作第一章..."）
  → 后台编排：创建项目 → 写入正典 → 创建 chapter-1.md → 触发生成
  → 编辑区流式展示生成文本
  → 生成完成 → 底部候选操作栏：[采纳] [需要修改] [拒绝]
  → 采纳 → 文本固化为正式章节，编辑器进入正常编辑模式
  → 侧边栏文档列表显示 chapter-1.md
```

### 错误与恢复

- 项目创建失败 → 编辑器内展示具体错误信息 + 可重试
- AI 生成失败 → 展示 API 错误详情（错误码 + 说明）
- 中断恢复（生成中关闭应用）→ 下次打开提示「上次生成未完成，是否重新生成？」
- 生成中可切换文档；切回时流式继续（状态由 FileFirstChapterStateStore 持久化）

## Consequences

- 状态机 `stepData` 需从 `Map<Step, String>` 扩展为支持多选值（`List<String>`）+ 自定义输入共存的数据结构
- `ProjectBrief.genreId` 单值字段需适配多题材（改为 `List<String>` 或分隔符拼接），影响 ContextCompiler 的题材注入逻辑
- 向导完成编排必须创建 chapter-1.md 文档并传递 documentId 给主界面导航——`onComplete` 回调签名变更
- editor_page 的 `_restoreFirstChapterWorkflow()` 成为第一章展示的统一入口，必须同时支持"向导直达"和"中断恢复"两条路径
- 正典面板是向导完成后修改设定的唯一入口（向导本身不可重跑）
- 与 ADR-0001 的关系：本 ADR 是 ADR-0001（引导型向导）的交互细化，不推翻其“跳过必须填充默认值”的状态契约——可跳过范围为书名、世界观、创意方向三步（世界观跳过时不注入正典，避免空值污染上下文）
