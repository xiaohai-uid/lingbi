# 保留历史的阶段重开与非线性推进模型

Workstream 不用简单指针回退处理返工，而采用"阶段内迭代 + 保留历史的阶段重开 + 独立代码回滚 + 独立发布回滚"四种分离动作。每个阶段维护 Attempt 数组和 Cycle 计数；重开时关闭当前尝试、记录原因、后续依赖产物进入 stale。不可逆事实（已发布版本、已执行迁移、已产生外部副作用）只能通过补偿动作处理，不能改写为"从未发生"。

## Considered Options

- **简单指针回退**: 把 phase 从 review 改回 design。rejected: 丢失失败历史，旧批准看起来仍适用于新版本。
- **每次返工新建 Workstream**: rejected: 同一产品问题的上下文碎片化，无法积累失败教训。
- **保留历史的重开机制（adopted）**: 兼顾审计完整性与返工灵活性，不可逆事实用补偿而非回退。

## Consequences

- 回退目标由"最早失效假设"原则确定，不机械返回前一阶段。
- 阶段内迭代（如测试失败后修复）不触发重开，Agent 可自主处理。
- 跨阶段重开（如 Review→Design）须用户或授权技术负责人确认。
- 重开传播：后续阶段进入 stale，产物不删除而标记为待重新验证。
- 产物重大修改后旧批准自动失效，须重新批准。
- Prototype 失败是研究结论而非项目失败，不得伪装为"未完成"。
- Workstream 是否新建取决于 Destination 是否改变。
