# ADR-0004: 灵笔相对 OpenWrite 的差异化决策

## 状态

已接受 (2026-07-25)

## 背景

灵笔以 OpenWrite 为功能基准全面蒸馏，但已有若干架构决策与 OpenWrite 不同，需明确处理方式。

## 决策

### 1. 内容层 = Skill 生态（差异化保留）

- OpenWrite 的题材引导知识内置于系统；灵笔改为由**题材 Skill** 承载
- 预装一套官方题材 Skill（玄幻/仙侠/都市/悬疑/言情/科幻/历史），确保开箱体验 = OpenWrite
- 社区可贡献/替换题材 Skill，这是灵笔的核心飞轮

### 2. 一键成剧 = 重量 Skill（超出 OpenWrite）

- OpenWrite 无此功能；灵笔新增
- 做成重量 Skill（走 Skill Runtime），输出格式随外部生图/生视频工具变化，社区维护更灵活
- 面向三类用户：小说作者、漫剧工作者、游戏开发者

### 3. 平行世界 = 双定位（超出 OpenWrite）

- 小说分支：写到某节点 → 分叉多条故事线 → 各自独立发展
- 成剧下游：基于已有 IP 资产生成不同版本的剧本/提示词
- 两者都要

### 4. 联网功能 = 分阶段

- **当前（local-first）**：用户用自己的 API Key + 内置爬虫工具自行获取市场数据（扫榜=导入榜单文本→AI分析；拆书=导入作品→AI拆解）
- **后期（商业化）**：租用服务器，付费功能迁移到服务端执行，防止本地逆向破解

## 后果

- 正面：保留 Skill 飞轮差异化；一键成剧/平行世界拓宽用户群；local-first 阶段零服务端成本
- 负面：预装 Skill 质量必须达到 OpenWrite 内置水平，否则开箱体验降级
- 风险：平行世界双定位增加复杂度，需明确 MVP 先做哪个（建议先做小说分支，成剧下游依赖一键成剧 Skill 完成后再接入）
