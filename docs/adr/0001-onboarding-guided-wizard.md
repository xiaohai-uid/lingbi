# Onboarding 采用引导型向导而非极简入口

现有 Onboarding 流程存在三个结构性缺陷：点击别处即卡死（状态机不处理中断）、跳过按钮不填充下游前置状态、模板必填项标为选填导致空数据进入生成链路。决定砍掉现有流程，重做为 3-5 步引导型向导（名字 → 题材 → 主角 → 世界观 → 第一章目标），每步可跳过但必须填充默认值，完成后直接触发第一章候选生成。

## Considered Options

- **A. 极简型（Notion 式）**：只问书名直接进编辑器。优点：最快进入；缺点：AI 生成缺乏上下文，首次生成质量差，用户第一印象仍然是"写作能力烂"。
- **B. 引导型向导（选定）**：3-5 步，每步可跳过有默认值，结束即生成第一章候选。优点：首次生成有足够上下文、用户立即看到产品核心价值；缺点：开发量大于 A。
- **C. 模板型（现有）**：选模板填大量字段。已证明失败：必填/选填约束错误、流程中断不可恢复。

## Consequences

- 跳过的步骤必须写入等价的默认状态（ProjectBrief 各字段不允许为空进入下游）
- 向导完成后系统必须处于"可立即生成第一章"的状态——这是状态契约，不是 UI 流程
- 现有 onboarding_wizard.dart (41KB) 将被替换而非修补
