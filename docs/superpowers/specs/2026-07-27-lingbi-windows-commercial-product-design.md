# LingBi Windows 商业化产品融合设计

日期：2026-07-27
状态：路线 2 已获用户确认，等待设计复核
目标平台：Windows Desktop（Flutter）
Figma：https://www.figma.com/design/zvw1hMIYRbukvoMN9evTdv

## 1. 决策摘要

LingBi 不做 OpenWrite 的表层复制，而采用“OpenWrite 的低门槛黄金路径 + LingBi 的深层创作能力”。默认体验只暴露完成一本书所需的下一步，高级工具按创作阶段渐进出现。

首要目标不是增加功能数量，而是让新用户在不阅读说明书的情况下完成以下闭环：

1. 选择题材。
2. 完成已预填的项目简报。
3. 配置或确认可用模型。
4. 创建世界观、人物库、大纲和章节计划。
5. 生成、审阅并保存第一章。
6. 退出后可恢复项目、对话、生成候选和版本。

任何只改变界面显示、没有改变运行时行为或持久化状态的“伪成功”均不算完成。

## 2. 产品经理审计

### 2.1 当前判断

LingBi 已拥有约七成商业创作产品所需的技术零件，但只有约三成形成了用户可交付体验。核心问题不是能力不足，而是能力之间缺少产品级编排。

| 维度 | 当前评价 | 主要证据 | 商业风险 |
| --- | --- | --- | --- |
| 技术广度 | 强 | 正典、画板、审稿、伏笔、知识库、模型路由等服务已存在 | 继续堆功能会增加维护成本 |
| 首次使用 | 弱 | App 配置向导较完整，项目创建仍是通用弹窗 | 用户无法快速获得第一份成果 |
| 项目创建 | 不合格 | 题材卡没有传参，创建时重复选择 | 第一处承诺立即失信 |
| 项目工作台 | 弱 | 创建后主要进入全屏聊天 | 用户不知道资料保存到哪里、下一步做什么 |
| 模型与 API | 部分可用 | 自定义端点和模型发现存在，运行时模型切换未闭环 | 可能展示已切换但实际请求仍用旧模型 |
| 数据资产 | 中等 | 引导结果写入 project_meta 与 Canon | 对普通用户不可见，价值感弱 |
| 高级工具 | 强但难发现 | 18 个工具面板多数接入真实服务 | 功能过载、缺少使用时机 |
| 可恢复性 | 中等 | 版本、候选、项目状态已有持久化 | 缺少统一回收站和面向用户的恢复中心 |
| 商业化准备 | 不足 | 有订阅、许可证、配额基础 | 缺少激活漏斗、可靠性指标和清晰价值分层 |

### 2.2 根因

- 欢迎页传递的是“创建项目”事件，而不是包含题材、平台和模板约束的 ProjectBrief。
- 引导流程产出的是内部 JSON/Canon 索引，而不是用户可直接管理的“项目资产”。
- AI、Skill、文件、模型和高级服务分别存在，没有统一 Agent Tool Runtime 把它们串成可观察的操作。
- 设置页承担了过多补救职责，关键配置没有在任务发生的位置就地解决。
- 导航按系统模块组织，而不是按作者的“构思—写作—审稿—发布”任务组织。

## 3. 竞品蒸馏边界与证据

OpenWrite v1.2.6 Windows 是裁剪后的 Flutter AOT 程序，无法恢复作者逐字 Dart 源码、注释和原始符号名。本设计只采用从官方 Windows 安装包、持久化结构、内置 Skills、工具描述和网络端点中能够验证的行为与架构，不使用无关的同名公开 Python 仓库。

已验证且值得吸收的能力：

- 对话代理与 `question`、`read_file`、`write_file`、`list_files`、`create_project`、`create_skill` 等工具协作。
- 项目以用户可理解的本地文件为核心，而不是隐藏状态。
- 内置小说写作 Skill：读取人物、世界观、摘要与最近章节；生成后先展示；确认后保存；再确认是否更新维护资料。
- Provider、Base URL、API Key、OpenAI/Anthropic 协议、模型发现与手工模型。
- 项目新建、导入、导出、回收站与恢复。
- 备忘录、Web 搜索、WebDAV 同步、Skill 创建与市场。
- 命名、蒸馏、拆解等高频创作快捷动作。
- 更新、公告、模型价格和用量相关基础设施。

## 4. 产品原则

1. **先成果后功能**：首次会话必须产出可见项目资产或正文候选。
2. **一次选择，全程继承**：题材、平台、受众、篇幅和风格只在用户主动修改时重新询问。
3. **AI 操作可观察**：显示读取了什么、准备写入什么、写入结果和失败恢复入口。
4. **写入须确认**：正文、人物、世界观和大纲变更先预览，再由用户采纳。
5. **本地优先**：项目可脱离云端打开、导出、备份和恢复。
6. **渐进披露**：新手只看到下一步；高级用户可进入完整工具箱和模型路由。
7. **运行时真相唯一**：界面选中的 Provider/模型必须等于下一次请求实际使用的 Provider/模型。
8. **Windows 优先**：首版只针对鼠标、键盘、宽屏和多窗口习惯优化，不承担移动端适配成本。

## 5. 信息架构

### 5.1 全局层

- 欢迎/最近项目
- 新建与导入
- Skills
- 同步与恢复
- 设置与模型

### 5.2 项目层

- **概览**：进度、核心资产、下一步、最近活动。
- **写作**：章节树、编辑器、AI 协作区。
- **设定**：人物、世界观、时间线、地点、物品。
- **大纲**：故事画板、章节规划、伏笔和叙事线。
- **审稿**：六维审稿、一致性、反幻觉、清晰度、去 AI 味。
- **资料**：参考书、向量知识、Web 搜索、备忘录。
- **发布**：市场情报、导入导出、版本和同步。
- **高级**：平行世界、一键成剧、模型路由、变更传播、Skill 管理。

默认不同时展示全部模块。导航根据项目阶段突出一项主任务，并允许高级用户固定常用工具。

## 6. 黄金路径

### 6.1 第一次启动

- 用户选择“纯本地”或“启用 AI”。
- AI 模式展示预设 Provider 和“自定义兼容接口”。
- 输入 Key 后发现模型；允许手工输入模型。
- 测试连接和短生成。
- 完成后返回原任务，不丢失刚才选择的题材和项目简报。

### 6.2 创建第一本书

1. 用户点击题材卡。
2. 打开侧边 Sheet，而不是清空上下文的通用弹窗。
3. Sheet 已填入题材，仅要求书名；平台、篇幅、一句话创意为可选项。
4. 显示“将创建”的资产清单。
5. 模型不可用时在 Sheet 内完成配置。
6. 创建项目后立即进入项目概览，后台准备核心资产。

### 6.3 项目初始化

项目必须产生用户可见的五类资产：

- 人物库
- 世界观
- 故事大纲
- 章节规划
- 创作备忘录

引导采用结构化问题卡；自由聊天仍保留，但不作为唯一交互。每个回答标明将更新哪个资产，用户可以编辑、跳过或稍后继续。

### 6.4 第一章

1. 概览显示“开始第一章”。
2. AI 读取核心资料、章节规划和最近章节。
3. 生成候选而不直接覆盖正文。
4. 用户选择采纳、局部改写、放弃或保存为备选。
5. 采纳后询问是否同步章节摘要、人物状态、伏笔和时间线。
6. 所有写入生成版本记录。

## 7. Windows 界面设计

### 7.1 欢迎页

- 左上品牌与全局搜索，右上模型状态、同步状态、设置。
- 主区域第一按钮为“开始一本新书”。
- 题材卡可直接点击，选中态必须明确，并把完整模板对象传给项目简报。
- 最近项目展示进度和下一项任务，而不仅是项目名称。
- 次级入口放置导入项目、恢复项目、浏览 Skills。

### 7.2 项目简报 Sheet

- 宽度约 520–640 px，避免阻断整个桌面上下文。
- 字段：书名、题材、目标平台、篇幅、目标读者、一句话创意。
- 题材来自入口并可修改，不能要求重复选择。
- 底部固定模型状态与“创建并开始构思”。
- 展示将自动创建的资产和本地保存位置。

### 7.3 项目概览

- 顶部：书名、题材、平台、总字数、同步状态。
- 左列：核心资产完成度和章节树。
- 中列：唯一突出“下一步”卡片；下面是项目资产和最近活动。
- 右列：AI 协作区，默认给出与当前阶段相关的建议，而不是空白聊天框。
- 用户打开章节后，中列切换为编辑器，右列切换为章节上下文。

### 7.4 AI 协作区

- 顶部模型选择器必须显示真实 Provider、模型、连接状态。
- 模式：问答、续写、改写、审稿、资料维护。
- 工具调用展示为状态卡：准备读取、已读取、等待确认写入、已写入、失败。
- 生成结果为候选卡，不直接覆盖正文。
- 高风险写入支持逐项或批量确认。

### 7.5 模型与自定义 API

- 快速选择器负责即时切换；设置页负责端点管理。
- 自定义端点字段：名称、Base URL、协议、Key、模型、认证方式、推理模型标记。
- 支持 `/v1/models` 发现、手工添加、连接测试和生成测试。
- 切换时更新 Provider 的运行时 `modelOverride` 或重建 Endpoint Provider，并验证 `AIService.currentModelId`。
- 自定义端点也必须出现在快速选择器中。

## 8. 领域与架构设计

### 8.1 ProjectBrief

创建入口统一传递不可丢失的项目简报：

```text
ProjectBrief
  title
  genreId
  templateId
  targetPlatform
  targetLength
  audience
  premise
```

欢迎页、市场情报、引导 Skill 和项目元数据只读取这一来源，避免各面板再次维护独立默认值。

### 8.2 ProjectAsset

将内部 `project_meta/*.json` 映射为用户可见资产：

```text
ProjectAsset
  id
  projectId
  type: character | world | outline | chapterPlan | memo | timeline
  title
  storagePath
  revision
  updatedAt
```

内部可继续使用结构化 JSON，但 UI 必须提供可编辑视图，并允许导出为 Markdown。

### 8.3 AI Endpoint Selection

`SettingsService.setSelectedModelId` 必须调用 AIService 的运行时模型切换接口。接口应保证：

- Provider 存在且可用。
- 模型选择写入持久化。
- Provider cache 得到更新。
- 下一次测试与生成读取相同模型。
- 切换失败时恢复旧选择并显示原因。

初始化阶段只注册一次自定义 Endpoint，消除当前重复注册。

### 8.4 Agent Tool Runtime

统一工具注册与审计层，首批工具：

- `question`
- `read_project_asset`
- `list_project_files`
- `write_project_asset`
- `create_chapter`
- `update_chapter_summary`
- `web_search`
- `create_memo`

每次工具调用记录输入摘要、目标、状态和结果，不记录密钥。写工具必须经过确认策略。

### 8.5 恢复与回收站

- 删除项目和重要资产默认移动到应用回收站。
- 回收条目包含原路径、类型、删除时间和项目 ID。
- 支持恢复和永久删除。
- 版本历史、生成候选和回收站入口统一放入“恢复中心”。

## 9. 功能蒸馏优先级

### P0：形成可销售的核心闭环

- 题材卡传递 ProjectBrief。
- 项目简报 Sheet 与就地模型检查。
- 项目概览与下一步任务。
- 用户可见核心资产。
- 运行时真实模型切换。
- 自定义 Endpoint 在快速选择器中可用。
- AI 候选、写入确认、版本与恢复。
- 第一章端到端验收。

### P1：吸收 OpenWrite 的高价值能力

- 统一 Agent Tool Runtime。
- 备忘录。
- 项目回收站。
- 命名、蒸馏、拆解快捷动作。
- 项目/Skills/备忘录 WebDAV 同步状态。
- Skill 创建向导及本地导入导出。
- 对话会话列表、重命名和项目绑定。

### P2：商业化差异化

- 按阶段编排 LingBi 的 18 个高级工具。
- 任务型模型路由与成本/质量策略。
- 市场平台模板与创作目标。
- 团队协作、授权、运营公告和可选遥测。
- 模板/Skill 市场的审核、版本和评分机制。

## 10. 商业化门槛

发布前必须满足：

- 首次创建到第一章候选的成功率可度量。
- 所有 AI 请求显示实际 Provider/模型。
- Key 只进入安全存储或明确标注的会话内存。
- 断网、余额不足、模型不存在和端点不兼容均给出下一步。
- 写入中断不破坏原正文。
- 项目可完整导出并在另一台 Windows 设备恢复。
- 订阅失败不应锁死用户自己的本地内容。
- 无授权的数据上传默认关闭。

核心指标：

- 创建项目完成率。
- 首次成果时间（Time to First Useful Output）。
- 第一章候选采纳率。
- 七日项目回访率。
- AI 请求成功率与模型切换失败率。
- 写入恢复成功率。
- 高级工具在正确阶段的启用率。

## 11. 验收场景

1. 从“玄幻”卡进入时，简报已选玄幻；创建后市场面板仍为玄幻。
2. 新用户没有模型时能就地配置自定义 OpenAI 兼容接口，完成后返回原简报。
3. 从模型 A 切换到模型 B 后，连接测试和正文生成请求都发送模型 B。
4. 创建项目后能看到五类核心资产以及明确的下一步。
5. 完成引导问题后，对应资产立即显示更新来源和时间。
6. 第一章生成只产生候选；拒绝不会修改正文；采纳会生成版本。
7. 删除项目后能从回收站恢复。
8. 退出并重新打开应用后，项目、当前任务、对话和未处理候选均可恢复。
9. 网络不可用时仍可编辑、保存、导出和查看历史。
10. 高级工具不阻塞新手路径，但高级用户可以搜索、固定和调用。

## 12. 非目标

- 当前阶段不开发 Android、iOS 或响应式手机布局。
- 不追求恢复 OpenWrite 原始源码或复刻不可验证的内部实现。
- 不在 P0 重写全部 18 个服务。
- 不以新增付费墙替代核心可靠性建设。

## 13. 实施顺序

1. 修复 ProjectBrief、模型运行时选择和已有未接线参数。
2. 建立项目概览和用户可见资产层。
3. 将引导从纯聊天改成结构化任务 + 可见产出。
4. 建立候选、确认、版本和恢复闭环。
5. 加入备忘录、回收站和统一 Tool Runtime。
6. 按创作阶段重新编排高级工具。
7. 完成 Windows release 构建、数据迁移和端到端验收。
