# LingBi 代码事实驱动的全套 Windows UI 设计

日期：2026-07-28

状态：用户已确认设计合同，等待书面规格复核

目标：让 Open Design 在理解 LingBi 当前代码、真实数据流和能力成熟度的基础上，重新设计全套 Windows UI。

## 1. 决策

采用“代码镜像式重做”。废弃现有 Open Design 稿的信息架构，只保留其中可用的 Warm Editorial 视觉语言。下一轮设计必须逐页映射当前 Flutter 页面、组件、控制器、工作流与服务，不得根据产品想象发明另一套导航、数据模型或成功状态。

现有 `lingbi-ui-review.html` 只能作为反例与局部视觉参考，不能作为新稿的结构底板。它使用“项目库 / 大纲 / 资产库 / 发布与恢复”等重新发明的主导航，并默认展示“已同步”、连接成功等缺少完整生产证据的状态，与代码中的 `ProjectTab`、页面入口和能力成熟度不一致。

## 2. 代码事实底板

### 2.1 应用壳与项目生命周期

`AppScaffold` 是 Windows 主工作区。它负责欢迎页、Skill 市场、设置、项目页、章节侧栏、顶部项目标签和 AI 面板的组合。项目内主导航必须严格使用代码中的五段 `ProjectTab`：

1. 概览：`ProjectOverviewPage`
2. 写作：`EditorPage`
3. 构思：`StoryboardPage`
4. 审稿：`ToolboxPage`
5. 发布：`ImportExportPage`

全局层包括：

- `WelcomePage`
- `ProjectBriefSheet`
- 打开与导入项目入口
- `SkillMarketPage`
- `SettingsPage`
- `CommandPalette`

上下文层包括：

- `TopBar` 与项目标签
- 当前项目和当前章节
- 实际 Provider / 模型状态
- 保存、离线和错误状态
- `Sidebar` 章节树
- `AiAssistantPanel` 的停靠或浮层状态

### 2.2 项目会话

`ProjectSessionManager` 是设计必须尊重的项目会话边界。创建、打开、最近项目恢复、章节选择和第一章创建都应表现为同一个连续会话，不允许 UI 绕过会话管理器形成重复项目状态。

会话应让用户看见：

- 当前项目；
- 当前章节；
- 最近项目恢复结果；
- 无效或已移动的最近项目；
- 第一章尚不存在时的创建动作；
- 重启后恢复的项目、章节和候选状态。

### 2.3 项目资产

项目概览围绕 `ProjectAsset` 的五种类型设计：

- 主角：`protagonist`
- 世界规则：`worldRules`
- 故事大纲：`outline`
- 开场设计：`openingScene`
- 第一章：`firstChapter`

每项资产必须能表达代码中的状态：

- 未开始：`notStarted`
- 生成中：`generating`
- 可编辑：`editable`
- 待确认：`awaitingConfirmation`
- 失败：`failed`

同时显示来源 `user / ai / imported`、修订号和更新时间。UI 不应把所有资产都画成已完成。

### 2.4 第一章安全链

第一章的核心数据流来自 `FirstChapterWorkflow`：

1. 读取项目资产。
2. 准备上下文和源版本。
3. 生成候选稿。
4. 等待作者确认。
5. 作者采纳、拒绝或取消。
6. 采纳时通过应用服务原子写入。
7. 保存可恢复状态，支持重启继续。

设计必须始终区分正文与候选稿。“生成完成”不等于“已写入正文”。候选的采用是显式动作；拒绝、取消、候选过期、写入失败和恢复都必须有独立状态。

## 4. 全套 UI 交付范围

Open Design 必须交付六组、二十四个核心画板。一个画板可以在同一画面内并列展示多个紧密相关状态，但不得省略所列状态。

### A. 启动与建项（5）

1. 欢迎页与最近项目

### B. 引导与概览（5）

8. 中断后的引导恢复

### C. 写作安全链（6）

12. 正常写作工作区
13. AI 候选生成中
14. 候选预览与差异

### D. 构思与审稿（3）

17. Storyboard 构思页
18. 审稿工具总览

23. Skill 市场与 Skill 详情

## 5. 能力成熟度合同

每张画板必须附设计注释，列出对应 Dart 入口、调用边界和成熟度。成熟度使用以下词汇：

- `REAL`：生产入口和关键数据流已存在，设计可表现真实可用状态。
- `PARTIAL`：存在页面或服务骨架，但端到端链路、持久化或外部验证不完整；设计必须显示限制和下一步。
- `PLANNED`：只有规划或未接入生产入口；不得作为可点击成功路径。
- `DISABLED`：出于安全或产品决策关闭；设计只可解释关闭原因和启用条件。
- `BLOCKED_EXTERNAL`：需要真实凭据、授权数据或外部证据；不得模拟成功。

已知示例：

| 表面 | 代码边界 | 状态 |
|---|---|---|
| 项目概览 | `ProjectOverviewPage` + `ProjectAssetRepository` | REAL，仍在演进 |
| 第一章候选 | `EditorPage` + `CandidatePanel` + `FirstChapterWorkflow` | REAL，关键路径 |
| 版本恢复 | `VersionHistoryPage` + `VersionHistoryService` | PARTIAL |
| WebDAV | `SettingsPage` + `SyncManager` + `WebDavService` | PARTIAL |
| 市场情报 | `MarketPanel` + `MarketIntelService` | BLOCKED_EXTERNAL（无可信数据源时） |
| 通用终端工具 | 无生产入口和审查通过的沙箱 | DISABLED |

最终事实包必须继续核对源码，不得把本表当作完整能力清单。

## 6. 行为与错误处理

### 6.1 通用交互状态

所有主要交互必须设计：

- 默认
- hover
- focus
- selected
- disabled
- 键盘焦点
- 加载
- 进度
- 可取消
- 超时
- 重试
- 部分完成

### 6.2 模型和端点

无模型或连接失败时保留用户当前任务，并允许就地配置后返回。界面显示实际端点、Provider、模型、延迟或错误。只有真实请求成功后才能使用成功状态。

### 6.3 本地优先与离线

离线时，本地编辑、保存、历史和导出继续可用。网络操作单独标为暂停、待重试或受限，不得让整个应用呈现不可用。

### 6.4 部分接通能力

WebDAV、恢复、版本、市场数据、授权及其他部分接通能力必须明确显示：

- 当前可用范围；
- 尚未接通的范围；
- 用户可采取的下一步；
- 是否会影响本地内容。

### 6.5 冲突与破坏性动作

本地/远端冲突显示基线、本地和远端版本，不自动覆盖。删除、替换、恢复和采纳等会改变数据的操作必须明确目标、影响和恢复方式。

## 7. 视觉系统

采用 Warm Editorial 的 Windows 版本：

- 暖纸张背景；
- 白色或轻暖工作面；
- 深墨色正文；
- 单一陶土色作为主强调；
- 绿色仅用于已经验证的成功；
- 界面使用清晰无衬线字体；作品标题和长文阅读可克制使用宋体；
- 以 8px 为基础间距，主要控件约 44px 高；
- 支持 1280–1920px Windows 宽屏；
- 章节、编辑器和 AI 面板可形成三栏，但 AI 面板在较窄宽度变为浮层；
- 使用统一线性图标，不使用 Emoji 作为主导航；
- 动效只用于解释加载、面板和状态变化。

禁止：

- 装饰渐变；
- 玻璃拟态；
- Emoji 主导航；
- 无意义浮动和卡片动效；
- 移动端页面或手机响应式布局；
- 用绿色、勾选或“已完成”掩盖未验证能力。

## 8. Open Design 输入合同

启动生成前，必须向 Open Design 提供一个完整、可核验的事实包，至少包含：

1. 产品目标和 Windows-only 约束；
2. `AppScaffold` 的页面组合与 `ProjectTab`；
3. `ProjectSessionManager` 的会话生命周期；
4. `ProjectAsset` 的类型、状态和来源；
5. `FirstChapterWorkflow` 的阶段和恢复路径；
6. 所有 `lib/ui_v2/pages` 和主要 `lib/ui_v2/components` 清单；
7. 相关服务与页面的映射；
8. `REAL / PARTIAL / PLANNED / DISABLED / BLOCKED_EXTERNAL` 矩阵；
9. 本规格的二十四个画板和视觉合同；
10. 现稿的具体偏差，明确禁止延续错误信息架构。

Open Design 需要先输出它理解的代码事实摘要和页面矩阵，再开始绘制。若摘要遗漏五段 `ProjectTab`、五项 `ProjectAsset` 或第一章候选安全链，运行结果直接退回，不进入视觉审阅。

## 9. 验收

生成结果必须同时满足：

- 二十四个画板全部存在；
- 每个画板能够回指代码入口和服务边界；
- 从玄幻题材卡到第一章候选的黄金路径无导航断点；
- 正文、候选、采纳和版本状态不会混淆；
- 无模型、失败、离线、冲突、恢复和外部受限状态均有设计；
- 导航严格对应五段 `ProjectTab`；
- 1280、1440、1600 和 1920px 宽度下结构成立；
- 不包含虚构服务、虚假成功、移动端布局、Emoji 主导航、装饰渐变或玻璃效果。

任何一项失败都进入修订，不得把“视觉完成”当作通过。

## 10. 非目标

- 本阶段不实现 Flutter UI。
- 不开发 Android、iOS 或手机布局。
- 不借此扩展后端能力或新建产品功能。
- 不宣称尚未验证的商业、安全、同步、市场或供应商能力已完成。
- 不恢复或复制 OpenWrite 的不可验证内部实现。
