### 手动测试发现的两个阻塞性问题

#### Bug A：第一章生成未展示（核心链路断裂）

**现象**：向导完成后跳转到空编辑器，左侧显示"暂无文档，点击 + 创建"，第一章候选正文不可见。

**根因分析**：
- `GuidedWizardPage._completeOnboarding()` 中 `trigger.fire(result).listen((_) {})` 是 fire-and-forget
- 事件流写入 `FileFirstChapterStateStore`，但 editor_page 的 `_restoreFirstChapterWorkflow()` 只在**打开已有文档时**触发
- 向导完成后没有自动创建/打开 chapter-1.md 文档，所以 editor 永远不会 restore 工作流

**修复方向**：向导完成后应自动创建 chapter-1.md 文档 → 导航到编辑器并打开该文档 → editor 的 `_restoreFirstChapterWorkflow()` 检测到 state store 中的 generating/candidateReady 状态 → 渲染 CandidatePanel 流式展示

#### Bug B：向导步骤交互类型错误

**现象**：所有 5 步都是同一个 TextField 自由输入，但"字数目标""发布平台""创意方向"应该是**选择题**（有预设选项卡片）。

**用户原话**：「有一些选项明明是B选项，你为什么还是给我整成选填啊？比如说字数平台，还有具体的创意哪些」

## 2. UX/UI 设计决策（已确认）

### 2.1 向导结构：两屏分组

| 屏 | 内容 | 交互形态 |
|----|------|---------|
| **第一屏：快速选择** | 题材 + 字数目标 + 发布平台 | 卡片网格，每组 3-5 个预设选项卡片，点选即高亮，支持多选（题材）或单选（字数/平台） |
| **第二屏：深度填写** | 主角描述 + 世界观 + 创意方向 + 第一章目标 | 混合：主角/世界观为自由文本（A 型），创意方向为卡片选择（B 型），第一章目标为自由文本（A 型） |

**每屏内布局**：垂直排列各维度，每个维度一个标题 + 描述 + 交互区（卡片组或输入框）。底部统一"下一步/完成"按钮。

### 2.2 B 型步骤交互：选择题卡片式

- 每个 B 型维度展示 3-5 个预设选项卡片
- 卡片样式：圆角矩形，内含图标/emoji + 标签文字 + 一行描述
- 选中态：边框高亮 + 背景色变化
- 每张卡片组底部有"+ 自定义"入口，点击展开 TextField
- 题材支持多选（如"玄幻+都市"），其余单选

### 2.3 B 型步骤预设选项

**由 AI 根据市场调研数据生成，用户审核后定稿。** 下一个会话的第一步应该是：
1. 读取 `assets/market/rankings/` 下的排行榜数据
2. 为每个 B 型维度生成 4-5 个高频选项
3. 输出选项列表供用户审核

初步框架（待 AI 生成+用户审核）：

| 维度 | 候选选项方向 |
|------|------------|
| 题材 | 玄幻、都市、悬疑、言情、科幻、历史、仙侠 |
| 字数目标 | 短篇(3-5万)、中篇(10-20万)、长篇(50万+)、连载(100万+) |
| 发布平台 | 起点、番茄、晋江、七猫、自由发布 |
| 创意方向 | 爽文升级、悬疑反转、虐恋情深、日常温馨、热血争霸 |

### 2.4 第一章生成展示：编辑器内流式

**完整用户旅程**：
```
向导第二屏点击"完成"
  → 创建项目 + 写入正典（后台，显示 loading）
  → 自动创建 chapter-1.md 文档
  → 导航到编辑器，打开 chapter-1.md
  → 编辑区显示流式生成文本（逐字/逐段出现）
  → 生成完成后，底部弹出候选操作栏：[采纳] [需要修改] [拒绝]
  → 用户点击"采纳" → 文本固化为正式章节
```

**关键 UI 元素**：
- 生成中：编辑区顶部显示进度条 + "AI 正在创作第一章..."提示
- 流式文本：正常渲染在编辑器中，带光标闪烁动画
- 候选操作栏：固定在编辑区底部的浮动 bar，三个按钮
- 采纳后：操作栏消失，文本变为普通可编辑状态

### 2.5 不需要对标 OpenWrite

用户明确表示：按灵笔自己的产品定位设计 UX，不严格复刻 OpenWrite 的交互。
