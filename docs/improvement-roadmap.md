## 方法论

每个改进项按 **用户价值 × 实现难度** 排序：

| 象限 | 说明 | 处理 |
|:----:|------|:----:|
| 🟢 高价值 + 低难度 | 立竿见影 | **立即做** |
| 🟡 高价值 + 高难度 | 核心壁垒 | **规划做** |
| 🔵 低价值 + 低难度 | 顺手做 | **有空做** |
| ⚪ 低价值 + 高难度 | 浪费时间 | **不做** |

### Sprint 2 详细说明

#### 2.1 Lorebook 系统（P0 核心）
```
概念: 类似 NovelAI 的 Lorebook
- 用户定义角色/地点/物品/规则的键值对条目
- 每个条目含：名称、类型、描述、激活关键词
- AI 生成时自动检测关键词，插入对应描述到上下文

实现路径:
1. 新增 lore_entry 表（Drift）
   id | worldId | type | name | content | triggerKeywords | enabled
2. 新增 LoreService
   - CRUD 操作
   - matchContext(text) → 返回匹配的 lore 条目
   - buildPromptContext(text) → 将匹配条目格式化为 prompt 上下文
3. 集成到 AI 生成管线
   - 在 LLM 请求前调用 buildPromptContext
   - 将结果注入 system prompt

文件: lib/services/lore/
```

#### 2.2 交互式生成
```
概念: 参考彩云小梦的交互模式
流程:
1. AI 生成一段正文（~500-800字）
2. 在流式输出末尾显示 3 个方向选项（AI 生成的）
3. 用户选择一个方向，或输入自己的指示
4. AI 根据选择继续生成

实现:
- 修改 state_machine 添加 branching 状态
- 新增方向选择 UI
- 每次续写前将已有内容和选择方向作为上下文
```
