## Phase 1：统一数据契约与唯一真源

### 目标
- 定义便携项目目录结构 v2
- 实现 Markdown + YAML frontmatter 正典格式
- 实现 JSON 运行态层
- 实现版本检测和自动迁移
- 保证旧项目可直接打开

### 非目标
- 不实现写作流水线
- 不实现 AI Agent
- 不实现世界线

### 输入
- Phase 0 完成的基线
- 架构文档中的数据分层设计

### 输出
- `ProjectMigrationService`：检测版本，自动补充新目录
- `CanonFileService`：Markdown 正典读写
- `RuntimeStateService`：JSON 运行态读写
- 目录结构：`.lingbi/runtime/`、`canon/`、`story/`、`outline/`、`style/`
- 迁移测试：旧项目 → 新项目无损

### 依赖
- Phase 0

### 风险
- 旧项目格式不统一（有些没有 .lingbi/project.json）
- 缓解：无 project.json 时从目录名推断项目名

- 集成测试：创建项目 → 写入正典 → 读取正典 → 验证 Markdown
- 回归测试：旧项目打开后内容不变

### 验收条件
- [ ] 新项目自动创建完整目录结构
- [ ] 旧项目打开后自动补充缺失目录，不修改现有文件
- [ ] 正典条目以 Markdown 存储，人可直接编辑
- [ ] 运行态 JSON 可读写
- [ ] 迁移前后 .md 文件内容 hash 不变

### 回滚方式
- 迁移只添加目录，不修改现有文件
- 回滚 = 删除新增目录

## Phase 2：Novel Action Surface

### 目标
- 实现统一的 Action Surface 接口
- 实现权限检查（AI 只能写 candidates/）
- 实现写作锁（文件级 + 进程内）
- 实现事务提交（写前快照 → 执行 → 提交/回滚）

### 非目标
- 不实现具体 Agent 逻辑
- 不实现 Context Packet 组装
- 不实现 UI 变更

### 输入
- Phase 1 的数据层
- 架构文档中的 Action Surface 设计

### 输出
- `NovelActionSurface` 抽象类 + 实现
- `WriteLockService`：文件锁管理
- `TransactionService`：快照 + 提交 + 回滚
- `PermissionGuard`：权限检查中间件
- 候选区管理：`candidates/` 目录读写

### 依赖
- Phase 1

### 风险
- 文件锁在 Windows 上的行为（文件被占用时无法删除）
- 缓解：使用 `.lock` 标记文件而非系统文件锁

### 测试
- 单元测试：锁获取/释放/超时
- 单元测试：事务提交/回滚
- 单元测试：权限拒绝（AI 写正典被阻止）
- 并发测试：两个操作同时请求同一章节

### 验收条件
- [ ] Action Surface 所有方法有权限检查
- [ ] AI 输出只能写入 candidates/
- [ ] 写作锁防止并发修改
- [ ] 事务失败时自动回滚到写前状态
- [ ] 锁超时后自动释放（防死锁）

### 回滚方式
- Action Surface 是新增代码，回滚 = 移除新文件
- 不影响现有 UI 和服务

## Phase 3：章节上下文与写作流水线

### 目标
- 实现 Context Packet 组装（15 层）
- 实现写作流水线状态机
- 实现 Planner Agent（章纲生成）
- 实现 Writer Agent（正文生成）
- 实现流式预览 UI

### 非目标
- 不实现审稿
- 不实现采纳 UI
- 不实现结算
- 不实现世界线

### 输入
- Phase 2 的 Action Surface
- 架构文档中的 Context Packet 设计

### 输出
- `ContextAssembler`：15 层上下文组装 + 裁剪
- `WritingPipelineStateMachine`：状态机实现
- `PlannerAgent`：调用 T1 模型生成章纲
- `WriterAgent`：调用 T2 模型生成候选正文
- `ModelRouter`：按任务分配模型等级
- UI：写作任务面板 + 流式预览

### 依赖
- Phase 2

### 风险
- Context Packet 组装需要多个数据源，性能可能成问题
- 缓解：缓存 + 增量更新，不全量重建
- 便宜模型输出质量不稳定
- 缓解：审稿在 Phase 4 补充

### 测试
- 单元测试：Context Packet 组装（各层正确填充）
- 单元测试：裁剪规则（超预算时正确截断）
- 单元测试：状态机转换（所有合法路径）
- 集成测试：完整写作流程（mock AI）
- Widget 测试：流式预览 UI

### 验收条件
- [ ] Context Packet 正确组装 15 层信息
- [ ] 超出 token 预算时按规则裁剪
- [ ] 状态机覆盖所有状态转换
- [ ] 流式预览实时显示 AI 输出
- [ ] 模型路由按任务类型分配正确等级
- [ ] 写作失败时回滚到 IDLE

### 回滚方式
- 流水线是新增功能，不影响现有 AI 对话
- 回滚 = 禁用 FeatureFlag

## Phase 4：审核、采纳与状态结算

### 目标
- 实现 Reviewer Agent（多维审稿）
- 实现采纳/拒绝 UI（diff 视图）
- 实现 Settler Agent（状态结算）
- 实现章节记忆（写后摘要）

### 非目标
- 不实现承诺/伏笔
- 不实现世界线
- 不实现 RAG

### 输入
- Phase 3 的写作流水线
- OpenWrite 37 维审稿思想（重新实现，不复制代码）

### 输出
- `ReviewerAgent`：审稿（连续性 + 风格 + 结构 + 角色一致性）
- `AdoptionService`：采纳/拒绝 + diff 展示
- `SettlerAgent`：提取事实 → 更新运行态
- `ChapterMemoryService`：生成章节摘要 + 客观观察
- UI：审核队列 + 采纳/拒绝按钮 + diff 视图

### 依赖
- Phase 3

### 风险
- 审稿质量依赖模型能力
- 缓解：审稿结果只是建议，最终由作者决定
- 结算可能提取错误事实
- 缓解：结算结果可人工修正

### 测试
- 单元测试：审稿报告结构
- 单元测试：采纳后候选移入正文
- 单元测试：结算后运行态更新
- 集成测试：写→审→采纳→结算完整流程
- Widget 测试：diff 视图 + 采纳按钮

### 验收条件
- [ ] 审稿报告包含至少 5 个维度
- [ ] 采纳后候选成为正式正文
- [ ] 拒绝后候选归档
- [ ] 结算后角色状态正确更新
- [ ] 章节摘要自动生成
- [ ] diff 视图正确显示变更

### 回滚方式
- 采纳前：候选仍在 candidates/，可删除
- 采纳后：通过快照回滚
- 结算后：运行态可从正文重新推导

## Phase 5：承诺、剧情线、角色弧光和伏笔

### 目标
- 实现叙事追踪数据模型
- 实现承诺生命周期管理
- 实现剧情线追踪
- 实现伏笔 DAG
- 实现角色弧光
- 审稿集成（到期承诺阻塞、过期伏笔警告）

### 非目标
- 不实现世界线
- 不实现 RAG
- 不实现自动检测（先做手动管理）

### 输入
- Phase 4 的审稿和结算
- 圆桌会议中的叙事追踪设计

### 输出
- `PromiseLedgerService`：承诺 CRUD + 生命周期
- `PlotlineLedgerService`：剧情线 CRUD + 进度
- `ForeshadowingService`：伏笔 DAG + 触发
- `CharacterArcService`：角色弧光追踪
- `MysteryService`：悬念管理
- 审稿集成：到期承诺 → 阻塞，过期伏笔 → 警告
- UI：叙事追踪面板

### 依赖
- Phase 4

### 风险
- 概念过多导致用户困惑
- 缓解：UI 只展示"需要注意"的条目，不强制管理

- 缓解：Phase 5 只做手动，自动检测延后

### 测试
- 单元测试：各生命周期状态转换
- 单元测试：DAG 无环验证
- 单元测试：审稿阻塞规则
- 集成测试：创建承诺 → 写章 → 到期 → 审稿标记

### 验收条件
- [ ] 承诺可创建、追踪、兑现/违背
- [ ] 剧情线可创建、推进、收束
- [ ] 伏笔可埋设、触发、过期
- [ ] 角色弧光可定义起点和终点
- [ ] 审稿时到期承诺标记为阻塞
- [ ] UI 展示需要注意的叙事条目

### 回滚方式
- 叙事数据存在 runtime/ JSON 中
- 回滚 = 删除对应 JSON 文件，不影响正文

## Phase 6：世界线候选未来

### 目标
- 实现世界线分叉
- 实现候选分支隔离
- 实现分支比较
- 实现分支采纳（通过写作流水线）
- 实现分支过期

### 非目标
- 不实现自动多分支推演
- 不实现分支合并冲突解决（先做覆盖式）
- 不实现可视化分支图

### 输入
- Phase 5 的叙事追踪
- 架构文档中的世界线模型

### 输出
- `WorldlineService`：分支 CRUD + 生命周期
- `BranchSnapshotService`：分叉时冻结正典快照
- `BranchComparisonService`：并排比较
- UI：世界线面板（创建/比较/采纳/归档）
- 隔离保证：分支操作不修改正史

### 依赖
- Phase 5（需要叙事追踪来比较分支差异）

### 风险
- 分支过多导致存储膨胀
- 缓解：过期机制 + 归档压缩
- 分支采纳后的连续性问题
- 缓解：采纳必须经过写作流水线（写→审→采纳→结算）

### 测试
- 单元测试：分叉创建（快照正确）
- 单元测试：分支隔离（分支操作不影响正史）
- 单元测试：过期机制
- 集成测试：分叉 → 写候选 → 比较 → 采纳 → 正史更新
- 铁律测试：生成世界线不修改正文、选择不修改正史

### 验收条件
- [ ] 分叉时正确创建正典快照
- [ ] 分支内写作不影响正史
- [ ] 比较视图正确显示差异
- [ ] 采纳经过写作流水线
- [ ] 过期分支自动归档
- [ ] 铁律：生成不修改、选择不修改、只有写作+采纳推进正史

### 回滚方式
- 分支数据在 candidates/worldlines/ 中
- 回滚 = 删除分支目录
- 正史不受影响

## Phase 7：RAG、语义记忆和成本优化

### 目标
- 实现通用 RAG 检索（基于向量索引）
- 实现语义记忆（跨章节知识图谱）
- 实现 token 成本统计
- 优化 Context Packet 组装性能
- 实现模型降级链

### 非目标
- 不实现云端向量库
- 不实现多人共享记忆
- 不实现自动学习用户风格

### 输入
- Phase 6 完成的核心流水线
- 现有 ZVec/JSON 向量存储

### 输出
- `RAGService`：向量检索 + 结果标注 [RAG_SUGGESTION]
- `SemanticMemoryService`：跨章节知识提取
- `CostTracker`：token 用量统计 + 成本估算
- `ModelFallbackChain`：T1→T2→T3 降级
- Context Packet 缓存和增量更新

### 依赖
- Phase 3（Context Packet）
- Phase 4（Settlement 提供记忆数据）

### 风险
- 向量检索质量依赖嵌入模型
- 缓解：RAG 结果只作为参考，不作为正典
- 成本统计不准确
- 缓解：使用 API 返回的 usage 字段

### 测试
- 单元测试：RAG 召回 + 来源标注
- 单元测试：成本统计累加
- 单元测试：降级链（T1 失败 → T2）
- 集成测试：RAG 结果不进入正典层

### 验收条件
- [ ] RAG 召回结果标注为 [RAG_SUGGESTION]
- [ ] RAG 结果不直接写入 Context Packet 正典层
- [ ] 成本统计按项目/章节/任务类型汇总
- [ ] 模型降级链正确执行
- [ ] Context Packet 组装 < 500ms

### 回滚方式
- RAG 是增强功能，禁用后回退到无 RAG 模式
- 成本统计是只读的，无副作用

## Phase 8：技能系统升级

### 目标
- 升级 Skill 声明格式（权限、触发、模型等级）
- 实现 Skill 权限沙箱
- 实现 Skill 与 Action Surface 集成
- 实现 Skill 触发条件

### 非目标
- 不实现 Skill 市场在线支付
- 不实现 Skill 版本自动更新
- 不实现第三方 Skill 审核

### 输入
- Phase 2 的 Action Surface
- 现有 SkillMarketplace 代码

### 输出
- `SkillManifest`：声明式配置解析
- `SkillSandbox`：权限隔离执行
- `SkillTriggerEngine`：条件触发
- 升级现有 17 个技能的声明格式
- UI：技能详情（权限、模型、触发条件）

### 依赖
- Phase 2（Action Surface）

### 风险
- 旧技能格式不兼容
- 缓解：无声明的技能使用默认权限（只读 + 生成候选）
- 权限沙箱在 Dart 中实现复杂
- 缓解：使用接口隔离而非进程隔离

### 测试
- 单元测试：声明解析
- 单元测试：权限拒绝（Skill 写正典被阻止）
- 单元测试：触发条件匹配
- 回归测试：旧技能仍可安装和使用

### 验收条件
- [ ] 新格式技能正确解析
- [ ] 技能不能写入 candidates/ 以外的位置
- [ ] 技能不能自行联网
- [ ] 旧格式技能使用默认权限仍可工作
- [ ] 触发条件正确匹配

### 回滚方式
- 技能系统是增量升级
- 回滚 = 使用旧版 SkillMarketplace

- [ ] 不破坏本地优先原则

### 回滚方式
