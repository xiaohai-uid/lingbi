## 三、一键启动器设计

### 3.1 启动流程

```
用户双击 lingbi.exe
  │
  ▼
启动器检查环境
  ├── Dart SDK 是否安装？ → 否 → 提示安装
  ├── Node.js 是否安装？ → 否 → 提示安装
  ├── 端口 8080-8091 是否可用？ → 否 → 提示冲突
  └── 依赖是否已安装？ → 否 → 自动 pub get / npm install
  │
  ▼
启动器显示主窗口 (服务状态面板)
  │
  ▼
用户点击"启动全部"
  │
  ▼
启动器按顺序启动微服务:
  1. API Gateway (:8080)
  2. AI Provider (:8081)
  3. Project (:8082)
  4. Document (:8083)
  5. Codex (:8084)
  6. Export (:8085)
  7. Version (:8086)
  8. Settings (:8087)
  9. Quota (:8088)
  10. Storage (:8089)
  11. Sync (:8090)
  12. Canvas (:8091)
  │
  ▼
等待所有服务就绪 (健康检查)
  │
  ▼
启动 Flutter 客户端
  │
  ▼
启动器最小化到系统托盘
```

### 3.2 状态管理

| 状态 | 说明 | 指示灯 |
|------|------|:------:|
| STOPPED | 服务未启动 | 🔴 红 |
| STARTING | 正在启动 | 🟡 黄 |
| RUNNING | 运行中 | 🟢 绿 |
| ERROR | 启动失败 | 🔴 红闪烁 |
| DEGRADED | 部分服务异常 | 🟠 橙 |

## 五、技术选型

| 模块 | 技术 | 说明 |
|------|------|------|
| **启动器 GUI** | Flutter Desktop | 与主应用共享技术栈 |
| **系统托盘** | system_tray / window_manager | Flutter 托盘插件 |
| **进程管理** | dart:io Process | 启动/停止子进程 |
| **Docker 编排** | docker-compose.yml | 官方 Docker 编排 |
| **社区网站** | GitHub Pages + Jekyll | 静态站点，零成本 |
| **Skill 注册表** | JSON + GitHub | 社区驱动，PR 提交 |
| **更新检查** | GitHub Releases API | 最新版本检测 |
| **日志查看** | 文件流 + 滚动视图 | 实时日志显示 |

## 六、数据流

### 一键启动流程
```
双击 → Launcher GUI → 环境检测 → 启动服务 → 健康检查 → 启动客户端 → 托盘驻留
```

### 社区更新流程
```
启动 → 异步检查 GitHub Releases → 版本比较 → 有更新？→ 通知用户 → 跳转下载
```

### Skill 安装流程
```
用户打开 Skill 市场 → 请求注册表 → 显示列表 → 点击安装 → 下载 Skill 文件
→ 复制到本地 skills 目录 → 注册到 Skill 管理器 → 完成
```
