# Codex Service 微服务调研

## 调研概述

针对 Codex Service（知识管理服务），调研了 20 个不同的技术解决方案，覆盖向量数据库、本地向量存储、知识图谱存储、语义搜索实现、实体关系管理、关系图谱可视化、实体消歧与合并、自动实体检测、版本化知识图谱、搜索性能优化等维度。

---

## 方案列表

### 方案 1: Chroma
**链接**: https://www.trychroma.com/

**特点**: 开源、轻量级、支持Docker/K8s部署，专为LLM应用设计。

**优点**: 
- 上手简单，API友好
- 支持多种embedding模型
- 内置元数据过滤
- 支持增量索引

**缺点**: 
- 单机性能有限（万级以下）
- 分布式能力较弱
- 文档相对较少

**适配度**: 4/5

---

### 方案 2: Qdrant
**链接**: https://qdrant.tech/

**特点**: 用Rust编写的高性能向量数据库，支持过滤、持久化。

**优点**: 
- 极致性能（Rust实现）
- 丰富的过滤能力（payload）
- 支持量化压缩
- 集群部署简单

**缺点**: 
- 社区规模相对较小
- 学习曲线略陡
- 商业化版本收费

**适配度**: 5/5

---

### 方案 3: Milvus
**链接**: https://milvus.io/

**特点**: 开源云原生向量数据库，支持大规模部署。

**优点**: 
- 成熟稳定（社区活跃）
- 支持多种索引类型（HNSW/IVF/IVF-PQ等）
- 与LangChain深度集成
- 强大的扩展性

**缺点**: 
- 部署复杂（依赖Pulsar/etcd）
- 资源占用较高
- 配置选项多，调优困难

**适配度**: 4/5

---

### 方案 4: Weaviate
**链接**: https://weaviate.io/

**特点**: 开源向量数据库，支持GraphQL API，内置AI模块。

**优点**: 
- GraphQL查询灵活
- 内置文本生成、图像生成等AI模块
- 支持向量压缩
- 云托管版本易用

**缺点**: 
- 性能不如Qdrant/Milvus
- 模块扩展需额外配置
- 文档质量参差不齐

**适配度**: 3/5

---

**优点**:

### 方案 7: Elastic Vector Search
**链接**: https://www.elastic.co/vectors

**特点**: Elasticsearch的向量搜索功能，支持dense和sparse向量。

**优点**:

### 方案 8: Typesense

## 推荐方案

### 综合推荐：Qdrant + Neo4j + BM25混合搜索

**理由**：

1. **向量存储**：Qdrant 提供高性能的向量搜索能力，适合大规模语义搜索。
2. **图存储**：Neo4j 提供专业的图数据库能力，适合管理实体关系。
3. **混合搜索**：BM25 + 向量混合搜索提供最高的召回率和精确度。

### 实施建议

1. **阶段一**：使用 Qdrant 作为向量数据库，SQLite vectors 作为本地备选
2. **阶段二**：集成 Neo4j 作为图数据库，管理实体关系
3. **阶段三**：实现 BM25 + 向量混合搜索
4. **阶段四**：添加 RAG 能力，结合 LLM 生成知识问答

这个组合既保证了性能，又保证了功能的完整性，能够满足灵笔对 Codex Service 的各种需求。
