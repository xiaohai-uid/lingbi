# Document Service 微服务调研

## 调研概述

针对 Document Service（文档管理服务），调研了 20 个不同的技术解决方案，覆盖文件同步策略、Markdown 处理库、实时协作框架、文档元数据管理、文档搜索、大纲与目录提取、文档导入导出、版本历史管理、文件冲突解决、存储效率等维度。

---

## 方案列表

### 方案 1: Git 集成同步
**链接**: https://git-scm.com/

**特点**: 将 Git 作为版本控制和同步后端。

**优点**: 
- 成熟的版本控制
- 分支和合并支持
- 历史记录完整
- 开源免费

**缺点**: 
- 学习曲线陡峭
- 不适合频繁小文件同步
- 需要 Git 客户端
- 冲突解决复杂

**适配度**: 4/5

---

### 方案 2: WebDAV 同步
**链接**: https://en.wikipedia.org/wiki/WebDAV

**特点**: HTTP扩展协议，支持远程文件管理。

**优点**: 
- 标准化：几乎所有云存储都支持
- 简单：基于HTTP，防火墙友好
- 支持双向操作（PUT/GET）
- 第三方工具丰富

**缺点**: 
- 性能一般，协议开销较大
- 不支持增量同步（需应用层实现）
- 大文件支持有限
- 冲突处理需应用层

**适配度**: 4/5

---

### 方案 3: S3 对象存储同步
**链接**: https://docs.aws.amazon.com/cli/latest/reference/s3/sync.html

**特点**: AWS CLI内置的S3同步命令，支持增量同步。

**优点**: 
- 官方支持，稳定性高
- 增量同步，效率高
- 支持多Region同步

**缺点**:

- 仅支持S3，不支持其他存储
- 依赖AWS CLI安装

**适配度**: 2/5

## 推荐方案

### 综合推荐：SQLite FTS + Git + markdown_it

**理由**：

1. **全文搜索**：SQLite FTS 提供零配置的全文搜索能力，适合文档搜索。
2. **版本控制**：Git 提供成熟的版本控制和历史记录。
3. **Markdown处理**：markdown_it 提供快速、可扩展的Markdown解析能力。

### 实施建议

1. **阶段一**：使用 SQLite FTS 实现文档搜索
2. **阶段二**：集成 Git 作为版本控制和同步后端
3. **阶段三**：使用 markdown_it 处理Markdown解析
4. **阶段四**：添加 Git diff + LZO压缩 实现高效版本存储

这个组合既保证了搜索性能，又保证了版本控制的可靠性，能够满足灵笔对 Document Service 的各种需求。
