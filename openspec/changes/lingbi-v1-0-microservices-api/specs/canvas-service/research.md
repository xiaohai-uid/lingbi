# Canvas Service 微服务调研

## 调研概述

针对 Canvas Service（故事画布服务），调研了 20 个不同的技术解决方案，覆盖Flutter画布库、Web图形库集成、图数据库可视化、节点拖拽交互、大图形性能优化、画布导出、协作画布、画布模板、画布版本管理、画布搜索与定位等维度。

---

## 方案列表

### 方案 1: flutter_flow_chart
**链接**: https://pub.dev/packages/flutter_flow_chart

**特点**: 流程图绘制库，支持多种节点形状，可自定义节点颜色、边框、文字样式，支持交互式连线、拖拽、缩放、保存/加载。

**优点**: 
- API设计简洁，上手容易
- 支持JSON序列化持久化
- 提供自定义节点类型
- 支持连接样式（曲线、分段、矩形）
- 支持自定义数据处理

**缺点**: 
- 节点类型有限，扩展性一般
- 对大图形的性能优化未提及
- 无原生协作功能
- 缺乏高级布局算法

**适配度**: 4/5

---

### 方案 2: vyuh_node_flow
**链接**: https://pub.dev/packages/vyuh_node_flow

**特点**: 高性能节点流编辑器，专为视觉编程、工作流编辑器设计，支持贝塞尔曲线连线、粒子动画、缩放、平移、快捷键、多选、迷你地图导航。

**优点**: 
- 高性能渲染（目标60fps）
- 丰富的视觉效果（粒子、渐变、流动虚线）
- 完整的主题系统
- 支持20+键盘快捷键
- 内置迷你地图和LOD（细节层次）
- 支持组和注释节点

**缺点**: 
- 依赖mobx状态管理，学习成本高
- API相对复杂
- 社区规模较小

**适配度**: 5/5

---

### 方案 3: diagram_editor
**链接**: https://pub.dev/packages/diagram_editor

**特点**: 交互式图表编辑器库，支持类型安全的组件和链接，提供平移、缩放、完整手势支持、序列化、Z轴排序。

**优点**: 
- 类型安全设计（泛型）
- 丰富的配置选项（连接端点对齐策略、链接样式）
- 支持自定义图层（背景、前景、覆盖）
- 支持父子节点关系
- 内置网格背景、高亮绘制器

**缺点**: 
- 相对较新，功能稳定性待验证
- 无内置布局算法
- 对大图形的性能优化未明确

**适配度**: 4.5/5

### 方案 4: 纯 Canvas API（Flutter）
**链接**: Flutter官方Canvas API

**特点**: Flutter原生的CustomPaint和Canvas类，提供底层绘图API，可绘制图形、路径、文本、变换等。

**优点**:

### 方案 5: D3.js via WebView
**链接**: https://d3js.org/

**特点**: JavaScript数据可视化库，提供选择、转换、比例尺、坐标轴、形状、交互、布局等功能，适合复杂数据驱动的可视化。

**优点**: 
- 功能极其强大和灵活
- 丰富的布局算法（力导向、树、Voronoi等）
- 庞大的社区和生态
- 支持动态绑定数据

**缺点**: 
- 学习曲线陡峭
- 需要通过WebView集成，增加复杂度
- 与Flutter代码交互需JSBridge
- 对大图形的性能需优化（虚拟渲染等）

**适配度**: 4/5

### 方案 12: 虚拟渲染（Virtual Rendering）
**技术方案**: 只渲染视口内的节点和连线，视口外元素不绘制。

**优点**: 
- 显著提升大图形性能
- 内存占用低
- 支持数千节点流畅滚动

**缺点**: 
- 需自行实现视口计算和渲染调度
- 连线跨越视口边界处理复杂
- 需结合QuadTree等空间索引算法

**适配度**: 4/5

---

### 方案 13: 分块加载（Chunk Loading）
**技术方案**: 将画布划分为多个块，按需加载和卸载。

**优点**: 
- 降低单次渲染压力
- 可与无限画布结合
- 便于实现懒加载

**缺点**: 
- 实现复杂度高
- 块间连线处理困难
- 需管理块状态

**适配度**: 4/5

## 推荐方案

### 综合推荐：vyuh_node_flow + D3.js via WebView

**理由**：

1. **核心画布**：vyuh_node_flow 提供高性能渲染（目标60fps），适合故事画布的大图形场景。
2. **布局算法**：D3.js 提供强大的布局算法（力导向、树、环形等）。
3. **性能优化**：vyuh_node_flow 内置LOD（细节层次）和迷你地图，支持大图形虚拟渲染。
4. **导出功能**：使用RepaintBoundary导出PNG，结合D3.js导出SVG。
5. **模板系统**：通过JSON模板定义常见故事结构。
6. **搜索与定位**：使用本地SQLite存储节点索引。

### 实施建议

1. **阶段一**：使用 vyuh_node_flow 作为核心画布组件
2. **阶段二**：集成 D3.js via WebView 提供布局算法
3. **阶段三**：实现模板系统和搜索定位
4. **阶段四**：添加协作画布（WebSocket + Yjs CRDT）

这个组合既保证了画布的性能，又保证了功能的完整性，能够满足灵笔对 Canvas Service 的各种需求。
